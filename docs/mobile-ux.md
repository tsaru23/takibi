# スマホでの使い方（設計メモ）

スマホで開いたときの使い方と、そこから決めた配置・操作・制約への対応をまとめます。実装は `index.html` にあります。

## 想定する使い方と方針

| 使い方 | 求めること |
|---|---|
| 寝る前に枕元に置く | 画面は暗く、操作は少なく。音が途中で切れないこと。うっかり触っても設定が変わらないこと |
| 作業中に横に立てておく（スタンドやケース） | 縦でも横でも崩れないこと。ときどき薪を足せること |
| 手に持って少し眺める | 片手の親指で届く範囲に、薪をくべるボタンがあること |

ここから決めた方針は4つです。

1. **何もしない時間を一番長く想定する。** 数秒操作がなければ操作UIは消え、映像と音だけが残ります。
2. **主役の操作は「薪をくべる」だけ。** 設定は、普段は畳んでおけるボトムシートに置きます。
3. **押しやすさを優先する。** ボタンやスライダーのつまみは 44px 以上にします。文字は本文15px、ラベル13〜14px以上です。
4. **音を止めない。** 画面ロックや別アプリへの切り替えがあっても、できる範囲で鳴らし続けます（後述）。

スマホ向けの配置は、幅が 600px 未満のとき、または横向きで高さが 480px 以下（幅 950px 以下）のときに使います。JavaScript が `body.m` というクラスを付け、CSS も同じクラスで切り替えます。タブレットとパソコンは、これまでの配置です。

## 画面の向きごとの配置

### 縦向き

```
┌──────────────┐
│ 薪 ▮▮▮▯ 3.4本 │ ← 上端（ノッチの下）
│              │
│              │
│     焚火      │ ← 映像（タップで薪をくべる）
│              │
│              │
│ [ 薪をくべる ] │ ← 親指の届く下側中央
│ ───  設定     │ ← ボトムシートのつまみ（下端、ホームバーの上）
└──────────────┘
```

- 「薪をくべる」ボタンは下側中央に置きます。大きさは高さ56px以上です。
- 設定は画面下から引き出すボトムシートです。
  - **閉**: つまみだけが見えます（高さ52px + 下端の安全領域）。
  - **半分**: 画面の高さの約46%です。焚火を見ながら音量を調整できます。
  - **全部**: 上端の安全領域の下まで広がります。
- シートが開いている間、「薪をくべる」ボタンは隠れます。シートの外をタップするとシートが閉じます。

### 横向き

- シートは画面の右側に置きます（幅は `min(420px, 画面の44%)`）。画面中央にある焚火を隠さないためです。
- 「薪をくべる」ボタンは左下です。
- 薪の本数の表示は左上です。ノッチ側の余白は `env(safe-area-inset-left/right)` で避けます。

## 操作の一覧

| 操作 | 場所 | 動き |
|---|---|---|
| タップ | 画面の中ほど | 薪をくべる |
| タップ | 画面の上端・下端の帯 | 操作UIを表示する（薪はくべない） |
| ボタン | 「薪をくべる」 | 薪をくべる |
| タップ | シートのつまみ | 閉 → 半分、開いていれば閉じる |
| 上下にドラッグ | シートのつまみ | 指に合わせて高さが変わり、離すと「閉・半分・全部」の近いところに止まる。勢いよく弾くと1段進む |
| タップ | シートの外 | シートを閉じる（薪はくべない） |
| タップ | 見出し（シーンと季節、焚火、環境音、季節の音） | その区切りを開閉する。畳んだ状態は覚えておく。初期状態では「シーンと季節」「焚火」だけ開く |
| ドラッグ | 画面（シートの外） | 視点を回す（カメラ操作の担当が実装） |

### 誤操作を防ぐ工夫

- **UIが消えている間に触っても、設定は変わりません。** 消えているUIは、タップを受け取りません。画面の中ほどのタップは薪をくべるだけです。
- **上端・下端の帯だけが「UIを出す」タップになります。** 帯の大きさは、上は安全領域 + 72px（画面の高さの20%まで）、下は 150px + 下端の安全領域（同じく30%まで）です。薪をくべるタップと取り違えにくい位置にしてあります。
- **画面をなぞっただけではUIが出ません。** 視点を回すドラッグや、スクロールの途中でUIが出入りしないためです。
- **シートが開いている間のタップは、閉じるだけです。** 設定を触ったあとに、うっかり薪をくべてしまうことがありません。
- **スライダーはシートの中で縦にスクロールできます。** つまみ以外の場所をなぞっても、値は動きません。
- **タップとドラッグの区別**は、映像側（`scene3d.js`）の入力処理が行います。この設計で必要な前提は、後述の「カメラ操作との分担」に書きます。
- ダブルタップでの拡大、長押しのメニュー、端からの引っ張り更新は止めています（`touch-action: manipulation`、`-webkit-touch-callout: none`、`overscroll-behavior: none`）。

## スマホ特有の制約と対応

### iOS Safari の音の自動再生

iOS Safari は、ユーザーの操作の中で始めた音しか鳴らせません。そのため「火をつける」のタップの中で、次をすべて行います。

1. `AudioContext` を作って `resume()` する。
2. 無音のバッファを1回鳴らして、出力を起こす。
3. `navigator.audioSession.type = 'playback'` にする（Safari 16.4 以降。マナーモードでも鳴り、バックグラウンドでも続きやすくなる）。
4. スマホでは、無音の `<audio loop>` の再生もこのタップの中で始める（次の項で使う）。

別アプリから戻ったとき、画面ロックを解除したとき、`AudioContext` が止まっていたら再開します。きっかけは、`visibilitychange`、`pageshow`、`focus` と、ユーザーの次のタップです。iOS では、止まった `AudioContext`（`interrupted`）を操作なしで再開できないことがあります。そのときは、次のタップで再開します。

### 画面ロックや別アプリに切り替えたときの音（2段構え）

パソコンのブラウザでは、タブを裏に回しても Web Audio は止まりません。音の出ているタブは、Chrome の省電力による間引き（intensive throttling）の対象外です。タイマーが1秒に間引かれても途切れないよう、音は 1.5 秒先まで予約しています。

スマホ、特に iOS では、画面ロックや別アプリへの切り替えで `AudioContext` が `interrupted` や `suspended` になり、音が切れやすくなります。一方、`<audio>` での普通のメディア再生は、Media Session を付ければバックグラウンドで続けられます。そこで次の2段構えにしています。

**第1段: Audio Session の指定。** 「火をつける」で `navigator.audioSession.type = 'playback'` にします。これだけで続く端末もあります。

**第2段: 録音したループへの切り替え。** スマホのときに働きます。パソコンでは、裏に回って `AudioContext` が止まったのを一度でも見たときから働きます。

1. **書き出し。** いまの設定の音（焚火、オンの環境音、季節の音）を、`OfflineAudioContext` で書き出して WAV にします。
   - 長さは180秒（約3分）、22.05kHz のステレオです。ファイルは約16MBで、メモリの中にだけあります。
   - 頭と終わりを5秒ぶん、等パワーでクロスフェードして、ループの継ぎ目をなくします。書き出した WAV を読み戻して、継ぎ目の差が普段の音の差の100分の1以下であることを確かめました。
   - 合成のコードは、ふだんの再生と同じものです。音の経路を作る `buildGraph(ctx)` と、予約を行う `audioTick(t)` に、出力先と時計を渡せる形にしてあります。書き出しのあいだだけ、状態の変数を書き出し用に入れ替えます。
   - ノードを全部先に作ると遅くなるので、6秒ぶんずつ `suspend` と `resume` で区切って予約します。パソコンでは、約3分ぶんの書き出しに10〜20秒かかります。`suspend` が使えない環境では、60秒に縮めて8秒ずつ予約します。
   - 書き出しが30秒より長くかかった端末では、次回から長さを短くします（最短60秒、×0.6ずつ）。画面が裏に回っていた間に長引いた場合は数えません。
   - 書き出しは、主スレッドを長く止めないよう小さく区切って進めます。書き出し中も、いまの再生は止まりません。
2. **常に鳴らしておく `<audio>`。** 「火をつける」のタップの中で、無音のWAVを `<audio loop>` で再生し始めます。iOS は、操作の中で再生を始めた audio 要素でないと、あとから再生できないためです。
3. **画面が見えなくなったとき**（`visibilitychange` で hidden、または `AudioContext` が止まったとき）、`<audio>` の `src` を録音ループに替えて再生します。ループが鳴り始めてから、Web Audio の出力を1秒かけて絞ります。途切れも二重もほとんどありません。ループで鳴らしている間は、見えない側の Web Audio の予約を止めます（電池のため）。
4. **画面が見えるようになったとき**、`AudioContext` を再開して、Web Audio を1秒かけて立ち上げ、ループを無音に戻します。`audio.volume` を変えられる環境では、ループも同時に絞ります。iOS は `audio.volume` が効かないので、Web Audio を0.4秒で立ち上げてからループを切ります。そのため、iOS では0.5秒ほど両方が鳴ります。
5. **Media Session。** 題名は「焚火」、アーティスト欄はシーン名、アートワークはアプリのアイコンです。ロック画面や通知の再生・一時停止は、どちらの経路で鳴っていても止められます。一時停止したあと、アプリで画面をタップすると再開します。

#### 設定を変えたときの反映

- 音量、パチパチの頻度と大きさ、環境音のオンオフと音量、季節、シーンの音の自動オンを変えると、**最後の変更から3秒後**に書き出し直します。
- 反映までの目安は、**変更から約15〜60秒**です（パソコンで約15秒、スマホではもっとかかる）。それまでに画面を裏に回した場合は、前の設定のループが鳴ります。表に戻れば、いまの設定の Web Audio に戻ります。
- 画面が裏に回っている間は書き出しません。表に戻ったときに、必要なら書き出し直します。
- 炎の強さが書き出し時から大きく変わったときも、書き出し直します（20秒おきに確認）。

#### ループにしかない・ないもの

- 映像と同期する音（火の粉の「バチッ」、鹿威し、鯉の「ちゃぽん」、蛙の喉の動きなど）は、ループには入っていません。画面が見えていないので、同期は不要です。シーンが鳴らす効果音（`TAKIBI.playSfx`）も入りません。
- 3分ごとに同じ音が繰り返します。薪が自動で足される設定のとき、炎の強さは一定の状態で書き出します。自動くべがオフなら、書き出した時点の強さで固定です。長時間（数時間）の裏再生では、薪が尽きる変化は音に出ません。
- 同時に書き出しているのは1つだけです。設定が変わると、書き出し中のものは捨てます。

#### 端末と OS で違うこと（できる範囲の対応）

- **画面ロック中も鳴り続けるかは、端末と OS に依存します。** iOS では、`<audio>` が鳴っていれば続くのが普通です。Android Chrome も、メディア通知が出れば続きます。省電力モードやメーカー独自のタスク管理で止められることがあります。
- iOS のロック画面には、`<audio>` 要素が鳴っている間だけ再生コントロールが出ます。ホーム画面に追加して開いたとき（PWA）の挙動は、ブラウザで開いたときと違うことがあります。
- Safari 以外のブラウザや古い OS では、`navigator.audioSession`、Media Session、`OfflineAudioContext.suspend` の一部が使えません。使えないものは飛ばし、残りで動きます。最悪の場合でも、これまでと同じ（Web Audio だけ）の動作です。

### 画面を消さない（Screen Wake Lock）

設定に「画面をつけたままにする」を足しました。この API に対応した端末だけ、行が出ます。初期値はオフです（枕元に置くときは、画面が消えるほうが望ましいことがあるため）。タブが裏に回ると自動で外れるので、表に戻ったときに取り直します。

### ノッチと下端のホームバー

`viewport-fit=cover` を指定し、`env(safe-area-inset-*)` で次を避けます。

- 薪の本数の表示と通知（上端）
- ボトムシートの下端と、その上の「薪をくべる」ボタン
- 横向きのときの左右の余白

シートの背景は画面の下端まで伸ばし、ホームバーの領域も同じ色で塗ります。

### 発熱と電池

- 映像の重さは、`scene3d.js` 側（ピクセル比の上限、草の量の自動軽量化）で抑えています。スマホで初めて開いたときの草の量は「少ない」です。選び直した値は、そのまま保存されます。
- 裏に回ったら、映像は止まります。ループで鳴らしている間は、Web Audio の予約も止めます。
- ループの書き出しは重い処理です。設定を変えるたびに走らないよう、最後の変更から3秒待ち、同時には1つだけにしています。
- 画面を消したいときは、「映像オフ（音だけ）」が一番省電力です。

### ホーム画面に追加（PWA の最小限）

`manifest.webmanifest`（名前「焚火」、`display: standalone`、暗いテーマ色）、192px と 512px のアイコン、`apple-touch-icon`、`theme-color` を置いています。アイコンは `tools/make-icons.py`（Pillow）で描いて書き出します。Service Worker によるオフライン対応はしていません。

## カメラ操作との分担

「1本指で回す、2本指で寄る」は、映像側の担当が実装します。この設計が `scene3d.js` の入力処理に求める前提は次のとおりです。

- **タップの判定**は、移動量と時間で行ってください。たとえば、移動が10px未満で、押してから離すまでが400ms未満ならタップとします。長押しとドラッグでは薪をくべません。
- **2本指**（寄る・つまむ）のときは、薪をくべないでください。指が2本になった時点で、そのタップは取り消します。
- タップだと判定したら、`pointerup` の中で同期的に `api.addLog()` を呼んでください。`index.html` は `window.TAKIBI.addLog` を差し替えて、その座標が上端・下端の帯なら薪をくべずに操作UIを出します。座標を明示するなら、`api.addLog({ x, y })` と渡せます。
- キャンバスの `touch-action: none` は、そのまま残してください。
- シートが半分のとき、画面下半分はシートに隠れます。焚火が隠れないよう、シートの高さに合わせて視点や画角をずらす場合は、`body.panel-open` クラスの有無を見てください。半分のときのシートの高さは、縦向きで画面の高さの約46%です。
